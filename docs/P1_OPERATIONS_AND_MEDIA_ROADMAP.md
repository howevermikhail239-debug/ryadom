# P1: фоновые задачи, уведомления и медиа

## Фоновые задачи

`POST /api/internal/jobs` выполняет два идемпотентных задания:

1. переводит просроченные `PUBLISHED`/`MATCHING` задачи без активного матча в `EXPIRED`;
2. доставляет Telegram-уведомления со статусами `PENDING` и retryable `FAILED`.

Запрос защищён `Authorization: Bearer <INTERNAL_JOB_SECRET>`. Если отдельный секрет не задан, сервер и Docker worker используют `AUTH_SECRET`. Для production рекомендуется отдельный случайный секрет длиной не менее 32 символов.

В Docker Compose сервис `worker` вызывает endpoint каждые 30 секунд. На Vercel, Render или другой платформе без постоянного worker нужно настроить защищённый cron-вызов этого endpoint с тем же Bearer-токеном.

Telegram retry использует экспоненциальную задержку, учитывает `retry_after`, ограничен шестью попытками и атомарно захватывает записи через PostgreSQL `FOR UPDATE SKIP LOCKED`/lease. Ошибки Telegram не откатывают бизнес-транзакции задач.

## Изолированные интеграционные тесты

Тест конкурентного Fast Match и expiry запускается только при наличии `TEST_DATABASE_URL`. URL должен указывать на отдельную, полностью мигрированную PostgreSQL/PostGIS базу:

```powershell
$env:TEST_DATABASE_URL="postgresql://.../microgigs_test"
npm.cmd test
```

Тест создаёт уникальные записи и удаляет только их. Никогда не указывайте рабочую production-базу.

## Текущее хранение фото

MVP хранит фото-отчёты как Base64 data URL в `Message.imageUrl`. Ограничения уже действуют: JPEG/PNG/WebP, до 600 КБ на клиенте, до 900 000 символов на сервере и не более 10 изображений пользователя на задачу.

Это приемлемо только для закрытого теста. Base64 увеличивает объём примерно на треть, раздувает PostgreSQL/WAL и заставляет API чата повторно передавать изображения при polling.

## Переход на S3-совместимое Object Storage

Перед публичным масштабированием:

1. подключить Selectel S3, Yandex Object Storage или другой S3-совместимый сервис;
2. добавить серверный endpoint выдачи короткоживущего presigned upload URL;
3. загружать файл напрямую из клиента, а в `Message.imageUrl` хранить только object key либо HTTPS URL;
4. проверять MIME, размер и сигнатуру файла на стороне storage-worker; удалять EXIF;
5. отдавать приватные фото через короткоживущий signed download URL только участникам задачи;
6. настроить lifecycle удаления после срока хранения и очистку orphan-объектов;
7. мигрировать старые Base64-записи пакетно, не блокируя чат.

До этого перехода не следует увеличивать текущие лимиты изображений.
