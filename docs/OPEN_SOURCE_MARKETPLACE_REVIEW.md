# Аудит open-source маркетплейсов

Дата проверки: 8 августа 2026 года.

Цель аудита — использовать проверенные продуктовые и архитектурные идеи, не перенося устаревший стек, небезопасные зависимости или код с несовместимой лицензией.

## Проверенные источники

| Источник | Состояние | Лицензия | Решение |
| --- | --- | --- | --- |
| [Sharetribe Go](https://github.com/sharetribe/sharetribe) | В README указано, что продукт больше активно не поддерживается | Sharetribe Community Public License, не обычная open-source лицензия | Код не копировать; использовать идеи машины состояний, блокировок и отложенных эффектов |
| [Sharetribe example processes](https://github.com/sharetribe/example-processes) | Активный набор примеров процессов | Apache-2.0 | Использовать как справочник по instant booking, подтверждению результата и change-request loop |
| [Cocorico](https://github.com/Cocolabs-SAS/cocorico) | Последняя активность основной кодовой базы — 2021 год | MIT | Код и Symfony-архитектуру не переносить; использовать идеи двусторонних отзывов и фонового истечения заявок |
| [TaskRabbit clone topic](https://github.com/topics/taskrabbit-clone) | Небольшая подборка разнородных демо-проектов без общего уровня качества | Зависит от репозитория | Не считать источником production-кода |
| `iqbalhasandev/taskrabbit-clone` | Репозиторий не найден или больше не публичный | Неизвестно | Не использовать |
| [Fleetbase Storefront](https://github.com/fleetbase/storefront-app) | Активный hyperlocal-проект | AGPL-3.0 | Не копировать код; использовать идеи auto-assign, зон обслуживания и доказательства выполнения |
| [AWS Last Mile Delivery Hyperlocal](https://github.com/aws-samples/aws-last-mile-delivery-hyperlocal) | Активный, но README помечает решение как требующее доработки | MIT-0 | Использовать только концепции ранжирования ближайших исполнителей и наблюдаемости |
| [TaskRabbit Playbook](https://github.com/taskrabbit/playbook) | Устаревший Rails-ориентированный материал | MIT | Сохранить принципы версионирования API, явной авторизации и whitelisted input |

Страницы `taskrabbit.github.io` и `medium.com/taskrabbit-engineering` не являются актуальной публичной документацией ядра TaskRabbit. У организации [TaskRabbit на GitHub](https://github.com/taskrabbit) нет открытого production-кода маркетплейса.

## Что внедрено

1. Критические переходы Fast Match и завершения выполняются транзакционно с блокировкой задачи и проверкой роли пользователя.
2. После назначения исполнителя цена и условия задачи заморожены для обычного заказчика.
3. Состояние «На подтверждении» вычисляется отдельно от «В работе».
4. Добавлен цикл «исполнитель отправил результат → заказчик подтвердил или вернул на доработку».
5. После завершения обе стороны могут оставить друг другу одну оценку; агрегированный рейтинг пересчитывается сервером.
6. На странице задачи показывается понятная история основных этапов сделки.
7. Telegram-уведомления создаются после успешной фиксации изменения состояния.

## Следующие улучшения

### P1 — перед публичным запуском

- Фоновый worker для повторной доставки записей `Notification` со статусами `PENDING` и `FAILED`.
- Идемпотентное истечение просроченных задач и уведомление заказчика.
- Централизованный сервис переходов статусов вместо распределённых проверок по API Routes.
- Ограничение частоты попыток входа и действий, влияющих на матчинг.

### P2 — после первых пользователей

- Опциональное фото результата и короткое окно для открытия спора.
- Радиус, расписание и категории, в которых готов работать исполнитель.
- Ранжирование кандидатов по расстоянию, рейтингу, доступности и скорости ответа.
- Волновая рассылка: сначала ближайшие исполнители, затем постепенное расширение радиуса.
- Категорийные поля в валидируемом `JSONB`, например вес груза или необходимые инструменты.

### Не переносить сейчас

- Полноценные календарные сетки аренды Cocorico.
- Переговоры по цене и длительные чаты из универсальных маркетплейсов: они противоречат сценарию «один тап».
- AWS-микросервисы, отдельный routing engine и постоянный трекинг исполнителя до появления реальной нагрузки.
- Зависимости и UI-код AGPL-проектов без отдельного юридического решения.

## Критерии заимствования

Перед использованием внешнего кода необходимо проверить лицензию конкретного файла, активность зависимостей, известные уязвимости и наличие тестов. Концепцию можно адаптировать самостоятельно; копирование кода допустимо только при совместимой лицензии и сохранении обязательных уведомлений об авторстве.
