# Аудит и реализация P1 — 2026-08-11

## Проверка входного рефакторинга

`RYADOM_REFACTOR.patch` совместим с текущей кодовой базой и проходит `git apply --check`. Архив не следует заменять целиком: он не содержит новые P1-функции и оставляет гонку повторного Fast Match.

Подтверждены и интегрированы полезные части: единый task workflow, общие policy/input-модули, единый расчёт срока, приватность геоданных до матчинга, быстрые ответы в чате, пауза polling скрытой вкладки, фильтр Telegram-верификации и корректные формулировки о платежах.

## Исправленные дефекты

### HIGH

- Fast Match: проверка idempotency выполнялась до блокировки; параллельный повтор мог получить ложный конфликт. Проверка перенесена после блокировки пользователя и задачи, добавлен retry Prisma `P2034` и raw PostgreSQL `40001` (`P2010`).
- Геоприватность: nearby API и detail-page передавали точные координаты и адрес до принятия. Для постороннего пользователя координаты округляются до трёх знаков, адрес скрыт; точные данные доступны заказчику, исполнителю и администратору.
- OTP: параллельные неверные коды могли обойти `maxAttempts`. Проверка, инкремент и погашение challenge теперь выполняются под `FOR UPDATE`; неверная попытка коммитится.
- Expiry outbox: падение процесса между `EXPIRED` и созданием уведомления теряло событие навсегда. Обновление задачи и запись outbox теперь атомарны.

### MEDIUM

- Срочная запланированная задача получала разные сроки при создании и редактировании. Общая функция задаёт `startsAt + 30 минут`; незапланированная срочная — 1 час, обычная — 2 часа.
- Telegram notification не имела настоящего retry worker и не создавала in-app событие без Telegram. Реализованы claim lease, `SKIP LOCKED`, exponential backoff, `retry_after`, лимит попыток и terminal-классификация 4xx.
- Docker worker завершался с Node exit code 13 из-за unsettled top-level await. Жизненный цикл исправлен и проверен в контейнере.
- Яндекс Карта перехватывала мобильный тап по фиксированной кнопке создания задачи. Карта помещена в отдельный stacking context.
- Проект импортировал `server-only`, но не декларировал пакет. Добавлен официальный MIT `server-only@0.0.1`.

## Реализованный P1

- Repeat Task через существующую форму и безопасный prefill только для владельца terminal-задачи.
- ETA исполнителя 5–180 минут на существующем `Bid.etaMinutes`, presets 15/30/60, обновление и уведомление заказчика; истёкшее ETA не показывается как актуальное.
- Режим доступности исполнителя 30/60/120 минут или выключен; доступные пользователи приоритетны в nearby-уведомлениях.
- `/notifications`, unread badge, individual/mark-all read.
- Telegram retry worker и защищённый internal jobs endpoint.
- Expiry worker для `PUBLISHED`/`MATCHING` без активного матча.
- Единый task workflow и status policy.

## Остаточные риски

1. Base64-фото допустимы только для MVP; план S3-миграции описан в `docs/P1_OPERATIONS_AND_MEDIA_ROADMAP.md`.
2. Для событий кроме expiry запись outbox следует в следующей итерации переносить внутрь той же транзакции, если потребуется защита от падения процесса в миллисекундном промежутке после commit.
3. Нет единого distributed rate limiter для task/chat/location API. Текущая защита наиболее критичного OTP присутствует; перед открытым запуском рекомендуется Redis/DB limiter.
4. Telegram Bot API не поддерживает idempotency key отправки: после сетевого успеха и падения до отметки `SENT` теоретически возможен повтор. Состояние БД и конкурентный claim идемпотентны, доставка имеет семантику at-least-once.
5. P2-функции намеренно не добавлялись: сначала стабилизирован и проверен весь P1.
